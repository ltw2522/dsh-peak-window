# 峰时守卫

发送消息前先看时间：峰时段拦一下让你确认，谷时快到峰时提醒一次。

## 判定口径

| 时段 | 判定 |
| --- | --- |
| 工作日 09:00–12:00、14:00–18:00 | 峰时 |
| 工作日其余时段 | 谷时 |
| 周六、周日 | 全天谷时 |
| 法定节假日 | 全天谷时 |
| 调休补班日（如 2026-02-14、09-20，官方调休上班的周末） | 全天谷时（不上浮） |

这套口径与用量计费插件（@kenz1117/dsh-ui-usage-billing）的峰谷胶囊一致，因此两处的"后转峰时"倒计时不会互相矛盾。

放假安排不用每年手改：插件会自动联网取当年与次年的数据，见下节。

## 峰时：发送前确认

在峰时给输入框写了内容、点「发送消息」（或按回车，默认开启），会弹出确认卡：

- 标题「当前为峰时」，下面一行「9h49m 后转谷时」；
- **继续**（红色）：按你刚才的方式真的发出去；
- **返回**（浅灰色）：什么都不发，草稿、附件、光标原样留在输入框里；
- **暂停，谷时自动恢复执行**（蓝色，独占一行）：把当前输入存档，等转谷时自动发出。

确认卡浮在输入框右上方，不遮挡正文，也不抢占输入焦点；按 `Esc` 等同「返回」。

### 暂停到谷时

点「暂停，谷时自动恢复执行」后：

- 当前草稿（原文，含换行）存进本机 localStorage，键 `dsh-peak-window:pending:v1`，刷新页面、重启 DSH 都还在；
- 卡片换成「已暂停，等谷时自动发送」，只给「知道了」，关掉不影响待发；
- 到转谷时那一刻（就是峰时卡上显示的 `Xh Ym`），插件把存下的文字写回输入框再走宿主自己的提交路径，等同你亲手点了一次发送；
- 发送前会检查三件事：**还是同一个会话**、**没有回合正在跑**、**输入卡不在投递中**。任一条不满足就原地等，不丢数据；
- 如果你中途切到了别的会话，会弹一次「暂停的对话不在当前会话」，切回去就会自动发（同一条提示 60 秒内不重复）；
- 设置里有一行「已暂停待发送 … 取消暂停」，随时能看到还挂着什么、也能一键取消（取消只清存档，输入框里的草稿不动）；
- 只存纯文本：附件本来就还在输入卡里，不需要搬。草稿为空（只剩附件）时点暂停等同「返回」。

## 谷时：临近峰时提醒

距下一次峰时不足「提前量」时：

- 点发送 → 消息**照常发出**，同时在旁边弹一张「距离峰时仅剩 Xh Ym」的告知卡，只有**知道了**（浅灰色）用来关掉它；这类提醒不拦发送，不会让你点两次；
- 按回车发送同理：内容照发，卡片只是提醒；
- 对话正在运行（且开着"对话运行时也提醒"）→ 同样弹一次，**不打断、不暂停**正在跑的回合；
- 开着"重复提醒"时，首次提醒之后每隔 t 再弹一次，直到真的进入峰时。**t 不允许大于提前量**，输入超限会被自动钳制。

## 设置

两个入口，改的是同一份设置，改完即时生效并记在本机浏览器里（localStorage 键 `dsh-peak-window:settings:v1`）：

- **设置 → 峰时守卫**：随时可打开的正式入口，不受时间影响；
- 卡片左下角的「设置」：手边刚好弹着卡时顺手改，改完点「完成」回到卡片继续选继续/返回。

可改的项：

- 谷时提醒提前量：`时` + `分`，1 分钟 ~ 24 小时
- 重复提醒：开关 + 间隔（分钟，上限等于提前量）
- 对话运行时也提醒：开关
- 回车发送同样拦截：开关
- 自动联网更新：开关（关掉就只用本地缓存与内置表，完全不发请求）
- 放假安排：显示当前用的是内置表还是已更新、上次更新时间，并带一个「立即更新」按钮

## 放假安排自动更新

内置表只是兜底，正常情况插件会自己更新：

| 层级 | 来源 | 什么时候用 |
| --- | --- | --- |
| ① | 刚拉到的网络数据 | 每次打开 DSH 或点「立即更新」时 |
| ② | 本机缓存（localStorage 键 `dsh-peak-window:holidays:v1`） | 断网、CDN 不可达、刚开机 |
| ③ | 内置表（2026 年，含 6 个调休补班日） | 从没联网成功过 |

- **数据源**：NateScarlet/holiday-cn（MIT 许可），每年国务院公布次年安排后由维护者更新 JSON；插件只是读它每年的 `{year}.json`。
- **两个 CDN**：fastly.jsdelivr.net 优先，失败自动换 gcore.jsdelivr.net，单次请求 6 秒超时。
- **取数范围**：今年 + 明年。明年文件在公布前是 404，属正常情况，不算失败。
- **刷新节奏**：启动时一次，之后每 30 分钟检查一次是否超过 12 小时有效期，过期才真的发请求。
- **失败降级**：拉取失败不清空旧数据，继续用缓存/内置表，只在设置里显示一行「更新失败，继续使用本地数据」。
- **隐私**：只发 GET，请求里不带任何本地内容，也不带账号信息；关掉「自动联网更新」后插件完全不发网络请求。
- **调休补班日**：数据里 `isOffDay=false` 的那几天（如 2026-02-14 周六上班）虽然要上班，但按**全天谷价**计，不套用 09:00–12:00、14:00–18:00 的峰时窗口；这类日期由数据源与内置表共同维护，不参与峰时判定。

## 想让提醒立刻出现

当前时间离峰时还早、又不想等的话，两种办法：

1. 把「提前量」临时调到 24 小时——只要下一次峰时在 24 小时内，下次点发送就会弹提醒，测完再调回去；
2. 直接在浏览器控制台执行 `__dshPeakGuardDebug.preview('peak')` 或 `preview('near')`，原地预览两种卡片，不发送任何内容。

## 已知边界

- 暂停的草稿只认当前浏览器：换浏览器、换电脑看不到它，也不会在那边自动发。

- 拦截靠输入卡上的「发送消息」按钮与回车事件；从菜单、快捷指令等其它入口发起的提交不经过这里。
- 按钮识别顺序：语言包精确文案 → 发送词根宽松匹配（认「发送消息（Enter）」这类带括号后缀的写法）→ `primary` 类名兜底 → 语言包缺失时退回「输入卡内最后一个按钮」。正在投递时（`data-sending`）不拦截，避免把「停止」当成发送。
- 卡片是普通浮层，不是模态框：它不会锁住页面，也不会暂停正在运行的回合。
- 只在浏览器端生效，换浏览器/清缓存后设置回到默认值。
- 峰时判定用本机时区，跨时区使用会跟着系统时区走。
- 放假安排依赖公开数据源；若数据源长期停更，插件会一直用最后一次取到的数据，此时可在设置里手动改回内置表（关掉自动更新）或改 `client.js` 的 `HOLIDAYS` 常量重新打包。

### 调试模式

- 入口：设置 → 峰时守卫 → 最下方「调试模式（仅本机）」开关；默认关闭。
- 强制档位：`按真实时间` / `强制峰时` / `强制谷时` / `强制临近峰时`。强制只改变"要不要弹卡、弹哪种卡"，不改写真实的峰谷计算；关闭调试即恢复。
- 时钟快进：`+1m` / `+10m` / `+1h` / `复位`。偏移只在本页有效，刷新即归零；放假缓存的 12 小时有效期仍按真实时间计算。
- 验证自动发送：峰时点「暂停，谷时自动恢复执行」后，连续快进到转谷时刻，即可看到草稿被写回并自动发出。
- 隔离性：开关存在本机 localStorage，不随包分发，也不影响其他用户的实例。
